# Public research and evidence features

The public feature components accept a `Dataset` and optional immutable `Publication`; they never import demo fixtures. Each page labels demo datasets and displays dataset identity, rubric version, date cutoff, publication identity, and declared coverage.

- `/scorecard/legislation` and `/scorecard/legislation/:id`: issue directory, editorial rationale, weight and reform position, original sources, party-at-vote roll call counts and member records. Missing records are explicitly unknown.
- `/scorecard/compare`: up to three members, issue and date scopes, presidential party context using party at vote, counts and evidence insufficiency. Historical member selection is supported. Different opportunities and issue mixtures are disclosed.
- `/scorecard/reports`: exact vote intersections and weighted rankings, party and chamber filters, active/historical status, per-party limits, CSV, SVG chart and print. Rankings omit unrated members; intersections retain exact matches regardless of score coverage. A saved report pins both validated query JSON and publication ID. A different loaded publication cannot silently reproduce the saved report.
- `/scorecard/archives`: immutable publication links and grade-change explanations distinguishing rubric, evidence/editorial corrections, and cutoff changes. Explanations do not infer behavior from corrected records.
- `RepresentativeFinder`: state selection with active Senate and House district listings, without address collection or implied district identification.
- `CorrectionForm`: a public evidence correction bound to publication plus member/vote. Disabled for demo/unpublished evidence, no contact information requested. POST `/scorecard/api/corrections` is validated by the publication backend.

`validateReportQuery` rejects unknown fields, IDs, outcomes, dates, parties, chamber and unsupported operations. `executeReport` evaluates only this finite schema over a supplied dataset; no arbitrary SQL or model-created facts. Conditions outside an issue/date scope produce an error instead of misleading zero matches. Missing records are never inferred as abstentions. Status and party filters describe the member in the pinned publication; presidential context uses party at vote.

Current party, current chamber and current status filters describe the selected publication's roster, including the last recorded affiliation for former members. Historical date filters narrow votes, not roster membership. UI, CSV, TSV and SVG metadata disclose these semantics. Research reports and comparisons recompute scores for the selected evidence scope; they are not frozen official publication grades. Archive grade comparisons use verified scoring snapshots where present, and explicitly label legacy current-engine recalculations. Archive downloads verify both dataset and scoring digests before display.

Optional natural-language input calls `/scorecard/api/research` with the question and loaded publication ID. The UI validates the interpreted query again and checks publication identity before using it. The server must configure the AI service and return an explicit unavailable/unsupported response when it cannot interpret a question. Structured research works independently. The interpreted query and source coverage remain inspectable.

CSV and copied TSV exports include the exact query, publication, rubric, coverage and source URLs and neutralize spreadsheet formula prefixes. TSV also removes embedded row/cell delimiters. SVG exports escape text, include visible dataset/publication attribution, and embed the full query, rubric, coverage, effective cutoff and source URLs in metadata. Charts display at most 30 results and disclose truncation. Print includes the current report table, exact query and source URLs. Quick presets provide the active member score sheet and the top ten in each major party.

Source citations are limited to evidence contributing to returned members, including direct intersection conditions even when the outcome is unscored. Unrelated votes in the wider scope are not cited. Future query end dates cannot move rubric lookback or decay beyond the publication cutoff. Archive comparisons validate the requested publication identity, cancel stale requests, include removed members, and preserve each frame's original evidence/source links.

Deployment still requires verified published data, approved editorial policy and configured backend bindings. This implementation does not create real congressional evidence, geocode addresses, or publish external corrections automatically.
